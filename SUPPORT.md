# Support

## Where to ask for help

Use the repository's structured issue forms for reproducible bugs and feature proposals.

Before opening an issue:

1. install the latest version from the default branch or the latest release;
2. check the README, validation guidance and existing issues;
3. reduce the problem to a minimal reproducible example;
4. remove credentials, private endpoints and all confidential or patient-identifiable data.

## Information to include

For technical problems, include:

- package version or commit SHA;
- Python version and operating system;
- installation method;
- command executed and complete error message;
- minimal configuration and synthetic input needed to reproduce the problem;
- simulation seed, horizon and warm-up period when relevant;
- expected and observed behaviour.

## Research and modelling questions

Questions about model assumptions should identify units, distributions, resources, constraints and the intended validation approach. Clearly distinguish exploratory or illustrative results from independently validated findings.

## Security and privacy

Do not open a public issue for vulnerabilities, credentials, confidential datasets or privacy incidents. Follow `SECURITY.md` and contact the maintainer privately through the contact information on the maintainer's public GitHub profile.

## Support boundaries

This project is maintained on a best-effort basis. No response time, operational support or clinical suitability is guaranteed. The software is intended for research and decision support and must be independently validated before operational use.
